# 윈도우 버전에 대하여

> 결론부터: **지금 코드로는 윈도우 버전을 만들 수 없습니다.** 이식이 아니라 재작성입니다.

## 왜 안 되는가

이 프로그램의 핵심 세 부분이 전부 macOS 전용 API입니다.

| 기능 | 현재 사용 API | 윈도우 |
|---|---|---|
| 시스템 오디오 캡처 | Core Audio Process Taps | ❌ 없음 → WASAPI 루프백으로 **재작성** |
| 마이크 캡처 | AVAudioEngine | ❌ 없음 → WASAPI 캡처로 **재작성** |
| 한국어 음성인식 | Speech / SpeechAnalyzer (무료·온디바이스) | ❌ **대체품 자체가 없음** |
| 화면 UI | SwiftUI | ❌ 없음 → WinUI·Electron 등으로 **재작성** |

Swift 자체는 윈도우에서 돌지만, 위 프레임워크는 전부 애플 것이라 한 줄도 옮겨갈 수 없습니다.

## 가장 큰 문제는 음성인식입니다

오디오 캡처와 UI는 품이 들 뿐 방법이 있습니다. 진짜 문제는 ASR입니다.

macOS 26은 **한국어 온디바이스 음성인식을 무료로 제공**합니다. 이 프로그램이 API 키 없이
돌아가는 이유가 이것입니다. 윈도우에는 같은 수준의 한국어 인식기가 OS에 없습니다.

선택지는 둘뿐입니다.

**A. whisper.cpp 로컬 실행**
- 무료, 오프라인 유지
- 모델 1.5GB 내려받아야 함, 첫 실행이 번거로움
- macOS 온디바이스보다 느림 (GPU 없으면 실시간의 1~3배 소요)
- 한국어 정확도는 비슷하거나 조금 나음

**B. 클라우드 API (ElevenLabs Scribe / 리턴제로 / CLOVA)**
- 설치가 가볍고 정확도가 가장 높음
- 시간당 과금, 오디오가 외부로 나감
- **맥·윈도우 양쪽을 같은 코드로 만들 수 있음** ← 이 점이 큼

## 권하는 방향

윈도우가 꼭 필요하시면, **B(클라우드 API)로 통일**하는 것이 맞습니다.
그러면 플랫폼별로 다른 부분이 오디오 캡처 하나로 줄어듭니다.

```
                 [ 공통 코어 ]
        클라우드 ASR · 용어교정 · 요약 · 템플릿
                      │
        ┌─────────────┴─────────────┐
   macOS 캡처                  Windows 캡처
   (Core Audio Tap)            (WASAPI 루프백)
```

UI는 Tauri나 Electron으로 한 번만 만들면 양쪽에서 씁니다.

### 대략의 품

| 작업 | 규모 |
|---|---|
| 윈도우 오디오 캡처 (WASAPI 루프백 + 마이크 2트랙) | 맥에서 겪은 것과 비슷한 수준의 난이도 |
| 클라우드 ASR 연동 + 기존 파이프라인 이관 | 중간 |
| 공용 UI (Tauri) 재작성 | 중간 |
| **전제 조건** | **ASR API 키와 과금 결정이 먼저** |

## 지금 결정하실 것

1. **윈도우를 정말 지금 해야 하는가?** 만드는 사람 본인이 쓸 용도면 맥만으로 충분하다.
2. **오디오를 클라우드로 보내도 되는가?** 사내 회의·수강생 음성이면 검토가 필요하다.
3. **월 얼마까지 쓸 수 있는가?** 90분 회의 하나에 대략 0.5~1달러 수준이다.

이 셋이 정해지기 전에는 윈도우 작업을 시작해도 방향이 계속 바뀐다.

## 참고 — 맥 버전 배포에 대해

지금 만든 `.app`은 **자체 서명(ad-hoc)** 상태입니다.
- 직접 빌드한 맥에서는 문제없이 쓴다 (첫 실행만 오른쪽 클릭 → 열기)
- **다른 사람에게 배포하려면** Apple Developer Program 연 $99 가입 후
  Developer ID 서명 + 공증(notarization)이 필요합니다. 이건 제가 대신 할 수 없습니다.
